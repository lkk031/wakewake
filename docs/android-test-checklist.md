# 第一阶段：Expo Go 基础测试

Expo Go 仅用于验证不依赖 `expo-notifications` 的界面和数据流程，例如 SQLite、CRUD、重复事项及提醒规则保存。Expo SDK 57 中通知能力在 Expo Go 内不可用；通知权限、调度、送达、点击和取消必须使用 Development Build 验证。

## 2. 启动 Expo Go

在项目根目录运行：

```bash
corepack pnpm --filter @wakewake/mobile exec expo start --go --clear
```

也可以在 Claude Code 中输入：

```text
! corepack pnpm --filter @wakewake/mobile exec expo start --go --clear
```

终端出现二维码后：

1. 确认手机与电脑位于同一个局域网。
2. 在手机上打开 Expo Go。
3. 点击 **Scan QR code**。
4. 扫描终端二维码。
5. 等待 JavaScript bundle 下载完成。

正常连接地址通常类似：

```text
exp://192.168.x.x:8081
```

不要使用手机无法访问的 `localhost` 地址。

## 3. 无法连接时

### 方案 A：使用 Tunnel

```bash
corepack pnpm --filter @wakewake/mobile exec expo start --go --tunnel --clear
```

Tunnel 需要互联网连接，首次运行可能需要下载 tunnel 依赖。

### 方案 B：检查 Ubuntu 防火墙

```bash
sudo ufw status
```

如果防火墙启用并阻止 Metro，可临时允许端口：

```bash
sudo ufw allow 8081/tcp
```

### 方案 C：清理旧进程和缓存

1. 在旧 Metro 终端按 `Ctrl+C`。
2. 重新运行带 `--clear` 的启动命令。
3. 关闭并重新打开 Expo Go。

# 第二阶段：Development Build 完整测试

独立 release APK 会将 WakeWake 作为 `app.wakewake.mobile` 安装在手机上，内嵌 JavaScript bundle，适合正式验证通知、后台运行和文件行为，且日常启动不需要 Metro。Development Build 仍可用于开发调试，但不是个人日用制品。

## 11. 电脑原生环境

需要安装：

- JDK 17。
- Android Studio。
- Android SDK。
- Android SDK Platform Tools。
- `adb`。

检查 Java：

```bash
java -version
```

建议显示 Java 17。

检查 ADB：

```bash
adb version
```

## 12. 手机开启 USB 调试

1. 打开“设置 → 关于手机”。
2. 连续点击“版本号”约 7 次。
3. 返回设置并打开“开发者选项”。
4. 启用“USB 调试”。
5. 用支持数据传输的 USB 线连接电脑。
6. 手机上出现 RSA 指纹询问时，选择“始终允许此计算机”并确认。

检查连接：

```bash
adb devices
```

正常结果类似：

```text
List of devices attached
ABC123456    device
```

如果显示 `unauthorized`，解锁手机并接受调试授权。

如果没有设备：

```bash
adb kill-server
adb start-server
adb devices
```

同时检查 USB 模式是否为“文件传输”。

## 13. 本地编译并安装独立 release APK

生成 Android 工程后，在项目根目录运行：

```bash
JAVA_HOME=/home/lkk/.local/jdk-17 \
ANDROID_HOME=/home/lkk/Android/Sdk \
ANDROID_SDK_ROOT=/home/lkk/Android/Sdk \
PATH=/home/lkk/.local/jdk-17/bin:/home/lkk/Android/Sdk/platform-tools:$PATH \
apps/mobile/android/gradlew \
  -p apps/mobile/android \
  assembleRelease \
  -PreactNativeArchitectures=arm64-v8a
```

预期输出为 `apps/mobile/android/app/build/outputs/apk/release/app-release.apk`。安装：

```bash
adb install -r /home/lkk/WakeWake-1.0.0-personal.apk
```

每个场景在操作前后都采集四层证据；Expo 持久 request 存在不能代替 live AlarmManager alarm：

```bash
adb shell dumpsys alarm | grep -n -A 8 -B 4 app.wakewake.mobile
adb shell dumpsys package app.wakewake.mobile | grep -E 'stopped=|enabled=|suspended=|hidden='
adb shell dumpsys notification --noredact | grep -n -A 8 -B 4 app.wakewake.mobile
adb logcat -d '*:S' Expo:V ReactNativeJS:V AndroidRuntime:E
```

依次测试并保存操作前后对比：

1. [ ] 前台、回到桌面和锁屏，分别登记仍在未来的提醒。
2. [ ] 编辑 `start` 锚点和 `due` 锚点时间，确认旧 alarm 被撤销且新 alarm 出现。
3. [ ] 创建两个具有相同 exact trigger 的不同事项，确认存在两条 logical key、native request 和 alarm。
4. [ ] 从 Recents 正常划掉后，立即复查 alarm 与 stopped/frozen 状态，并等待实际投递。
5. [ ] 普通进程死亡后复查同一组证据。
6. [ ] 单独标记 Force stop 测试；不期待投递，重新打开后确认首次 active 强制重建。
7. [ ] 重启手机后复查未来提醒恢复与实际投递。

结果分类：

- alarm 仍在但晚到：记录为非精确调度、Doze 或 OEM 投递延迟。
- alarm 被 OEM 删除、包未运行：WakeWake 无法当场自我恢复；重新打开或调整 vivo 电池/自启动/后台设置后才能重建。
- 包处于 stopped state：必须由用户重新打开；不得写成后台方案可绕过 Force stop。
- 重新打开后重建成功：只证明 first-active 修复有效，不等于划掉后台期间保证投递。
